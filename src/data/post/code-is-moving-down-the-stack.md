Delete this block when the draft is written.

DO NOT write "the death of coding." The genre is exhausted, it is wrong, and it
would cost the series its credibility with the exact readers it wants. The piece
is more interesting when it argues that code persists and relocates.

THESIS
Code isn't disappearing; it's moving down the abstraction stack. Programming and
writing code have never been the same activity — and the layers above finally
make the difference legible.

THE SPINE
1. Open with the historical pattern, because it defuses the reflex. Assembly did
   not kill programming; it moved it. Nobody hand-allocates registers, and the
   people who used to are not unemployed — they became the people who write
   compilers and the people who write in C. The volume of assembly executed today
   is higher than ever. It just isn't typed by hand.
2. The distinction that carries the piece: programming is deciding what the system
   does; writing code is expressing that decision in a language a machine runs.
   We conflated them because for sixty years code was the only place a decision
   could be written down. It absorbed every decision from above by default — not
   because it was the right home, but because it was the only home.
3. Reframe what an agent writing code actually is. Not "the programmer is being
   replaced" — the *transcription* is being automated, while the deciding stays
   put. And the reason today's agents feel unreliable is that we ask them to
   decide and transcribe in the same jump, then only show us the transcription.
4. Where the programmer moves: upward, into the layers this series has been
   describing. Naming the operations. Settling the vocabulary. Deciding what a
   precondition should be. This is not a consolation prize; it is the part of the
   job that was always the actual job.
5. What stays at the code layer, honestly. Performance work. Novel algorithms.
   The genuinely irregular. The integration with the system that has no model.
   Debugging when the abstraction leaks — and it will. Give this real space; a
   piece that pretends code becomes trivial will be dismissed by the people who
   maintain it.
6. The uncomfortable part, stated rather than dodged: this changes what junior
   work is, and the traditional path into the profession ran straight through the
   transcription that is being automated. Do not resolve this cheaply. Naming it
   honestly is worth more than an optimistic answer.
7. THE HANDOFF SECTION (required in every piece — see planned_posts.md).
   In, from the Execution Model — "Generation": the code implements a contract it
   did not invent. That is not new; it is what every scaffold and client generator
   has done for years. What changes is how much of the contract arrives specified.
   Out, to Technology Stack — "Binding": frameworks, packages, the substrate. This
   handoff has been solved so long nobody calls it a handoff — `import` is a
   handoff. Worth naming, because it sets up the next piece: if binding is this
   settled, why is choosing what to bind to the first decision anyone makes?

PRIOR ART
COBOL's "programming in English" promise. 4GLs. CASE tools. MDA and UML codegen —
the cautionary tale, and it must be addressed head-on, because the informed
reader is already thinking it. The honest answer is that MDA tried to generate
code from models nobody could keep accurate, with no feedback loop and no way to
state semantics; the models were drawings. Low-code. Copilot and coding agents.

DNA'S ONE NOVEL CLAIM
Nothing here is a claim about DNA — this piece is a consequence, not a product
argument. Its job is to make the relocation feel inevitable rather than
threatening. Resist the urge to close with a product pitch; one link at the end
is plenty.

FIGURE — interactive (house standard; see planned_posts.md)
The relocation, made literal. A single "where do decisions get made" slider across
the eras: hand-written assembly → compiled languages → frameworks → agents writing
code → the full ladder. As the reader moves it, two bands move in opposite
directions: what a human writes shrinks, what a human decides stays roughly
constant and moves upward. The historical eras on the left are settled fact, which
is what earns the last position on the right.

The reason this beats prose: the piece's whole claim is that two things people
conflate — writing code and programming — move independently. A control that
separates them shows it in one gesture.

Do NOT reuse the three-era stack figure (Human → Code → Machine, etc.). It does
